# Запуск в Telegram и хостинг

## Как это работает на GitHub

В репозитории два workflow, оба используют один и тот же код и одну concurrency-группу
`telegram-bot-…`, поэтому **два polling-процесса никогда не пересекаются**.

1. **`telegram-host.yml` — постоянная работа.** Запускается по расписанию каждые
   6 часов, держит бота 5ч45м, следующий запуск поднимает его сразу после предыдущего.
   Ручной запуск: *Actions → Telegram - hosted bot → Run workflow* (можно задать
   длительность в минутах).
2. **`telegram-demo.yml` — приёмочная проверка.** По кнопке *Run workflow* (или при
   push в рабочую ветку) проверяет тесты, Bot API и поднимает живую сессию на 5–348
   минут. Это проверка прототипа, а не постоянный хостинг.

Обоим нужен только один секрет — `TELEGRAM_BOT_TOKEN`. ИИ-слой работает через
бесплатные **GitHub Models**: workflow уже содержит `permissions: models: read` и
передаёт `GH_MODELS_TOKEN: ${{ github.token }}`, поэтому отдельный ключ не требуется.
Если GitHub Models недоступны или лимит исчерпан, бот автоматически продолжает
отвечать на правилах базы — клиент всё равно получает проверенный ответ или честный
отказ.

### Расписание и ограничения GitHub Actions

- GitHub Actions — не выделенный сервер: cron может задерживаться на десятки минут,
  а между запусками возможен короткий перерыв.
- GitHub отключает расписание после 60 дней без активности репозитория; включается
  обратно кнопкой *Enable workflow*.
- Бесплатные минуты: для публичного репозитория стандартные раннеры не тарифицируются.
  Для длительной работы на приватном репозитории проверьте лимиты аккаунта.
- Лимиты GitHub Models (порядка 10–15 запросов в минуту и 50–150 в сутки для
  бесплатного уровня) при превышении переводят бота в режим правил; код учитывает это
  заранее (`LLMRouter` + предохранитель на 3 ошибки).

## Безопасная настройка секрета

1. Откройте https://github.com/nigerader-dev/TGbot/settings/secrets/actions
2. Создайте **Repository secret** `TELEGRAM_BOT_TOKEN` со значением токена от
   @BotFather. Не вставляйте токен в YAML, issue, README или код.
3. В настройках Actions включите workflow, если он выключен.
4. Запустите `Telegram - hosted bot (GitHub Models AI)` вручную и проверьте, что шаги
   «Validate the knowledge base», «Check the AI layer» и «Run the Telegram bot» прошли.
5. Ссылка на бота печатается в summary приёмочного workflow (job *Prepare and verify
   Telegram*); токен в артефакты и summary не попадает.

Если ИИ-модель нужно заменить (например, на корпоративный шлюз или локальную Ollama):

```yaml
env:
  LLM_PROVIDER: custom          # или ollama, openai, openrouter, groq, ...
  LLM_BASE_URL: https://ai.example.internal/v1
  LLM_MODEL: my-small-model
  LLM_API_KEY: ${{ secrets.LLM_API_KEY }}
```

Ключ хранится только в секретах репозитория. `AI_ENABLED=0` полностью выключает
ИИ-слой: бот продолжит работать на детерминированных правилах.

## Полноценный хостинг вне GitHub (24/7)

В репозитории есть `Dockerfile` и `docker-compose.yml`; процесс поднимает веб-демо,
`/health` и Telegram long polling одновременно.

```bash
git clone https://github.com/nigerader-dev/TGbot && cd TGbot
cp .env.example .env      # заполните TELEGRAM_BOT_TOKEN и, при желании, LLM_*
docker compose up -d --build
```

Подходит любой хостинг с постоянным процессом и исходящей сетью:

- **VPS / выделенный сервер** — команда выше; для автозапуска добавьте
  `restart: unless-stopped` (уже включено) или systemd-юнит.
- **PaaS (Fly.io, Koyeb, Railway, Render)** — деплой Docker-образа, переменные
  окружения из `.env.example`,health-проверка на `/health`. Для бесплатных тарифов
  проверьте, что сервис не засыпает: при засыпании polling останавливается.
- **GitHub Codespaces** — только для ручного теста, не для постоянной работы.

Не запускайте два процесса с одним `TELEGRAM_BOT_TOKEN`: второй получит конфликт 409
и остановится с понятным сообщением (это защита, а не ошибка).
