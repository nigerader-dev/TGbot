# Запуск в Telegram и публикация

## Важно про GitHub

GitHub хранит исходный код. GitHub Pages не выполняет Python и не может обслуживать
Telegram long polling. **Actions не используется как постоянный сервер.**

Для ручной приёмочной проверки подготовлен workflow
`.github/workflows/telegram-demo.yml`: он проверяет реальный Bot API и запускает
бота на **15 минут**, после чего аккуратно останавливает его. Ручной выбор длительности
предусматривает 5, 15 или 30 минут. Бесконечных расписаний и автоматического продления нет.

Нормальный постоянный запуск выполняется на отдельном сервере или контейнерном
хостинге командой `python -m service_bot telegram`. Dockerfile включён в репозиторий.

## Безопасная настройка Actions

1. В настройках репозитория откройте:
   https://github.com/nigerader-dev/TGbot/settings/secrets/actions
2. Создайте **Repository secret** с именем `TELEGRAM_BOT_TOKEN` и значением токена,
   полученного у @BotFather. Не вставляйте токен в YAML, issue, PR, комментарии или код.
3. Если Actions выключен, включите его в настройках репозитория.
4. Workflow запускается при push в `arena/01a0fe03-tgbot`. Для повторной проверки
   существующего запуска после добавления секрета нажмите **Re-run all jobs** в Actions.
   `workflow_dispatch` применим после появления файла workflow в default branch.
5. Дождитесь успешного шага **Verify real Telegram API**. Ссылка на действительного
   бота появится в summary и артефакте `telegram-connection-public`.
6. Во время шага **Manual live Telegram acceptance session** откройте эту ссылку,
   отправьте `/start` и четыре тестовых вопроса. После окончания шага бот остановится.

Если в Actions видна ошибка «Create the TELEGRAM_BOT_TOKEN…», секрет не настроен.
Если Bot API отклонил токен или найден webhook / конфликт polling, исправьте причину
и перезапустите приёмочную проверку. Успешная публикация кода не означает, что бот
подключён: это отдельные, проверяемые этапы.

Секрет доступен только шагам проверки токена, проверки Bot API и работы Telegram.
Он не передаётся шагам установки зависимостей, тестов или загрузки артефактов.
Публикуемые данные включают только проверенное имя бота, ссылку, время проверки и
версию базы. Содержимое входящих Telegram-сообщений и токен в артефакт не попадают.

В этой сессии подключение Arena не имеет права записывать Actions Secrets (HTTP 403).
Наличие уже настроенного секрета и реальное подключение подтверждены workflow.
Если понадобится изменить секрет, это делает владелец через интерфейс GitHub либо
после переподключения Arena с необходимыми правами. Перед постоянным размещением перевыпустите токен, если он
ранее был отправлен в чат, и обновите секрет.
